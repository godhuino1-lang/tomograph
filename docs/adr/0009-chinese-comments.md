# 9. 代码注释与文档统一用中文

- 状态：已接受
- 日期：2026-10
- 相关：[ROADMAP](../../ROADMAP.md)（开源首发清单里的"英文 README"）、[glossary.md](../glossary.md)

## 背景

项目作者（也是这个项目目前唯一的读者和贡献者）在读代码时指出：注释是英文的。

**读不懂的注释等于没有注释。** 而这个项目的注释里承载了大部分设计推理——"为什么不那样做"、
"这里踩过什么坑"——它们不是装饰，**它们就是这个项目最有价值的部分**。

## 决策

1. **代码注释与 javadoc 用中文**，包括类注释、方法注释、行内注释、`<p>` 段落与列表。
2. **标识符与协议实体保持英文**：`TomographSpan`、`gen_ai.request.model`、`doChat`、
   `startTimeUnixNano`、`COMPUTE_MAXS`…… 因为它们是代码和规范里的**实体**，
   翻译它们只会制造两个对不上的名字。中文解释围绕它们展开。
3. `docs/` 下的文档本来就是中文，不需要改。
4. **git 提交信息保持英文**：`git log` 是公开门面的一部分，而且它和代码注释服务的是不同读者。
   （如果你想让提交信息也改中文，说一声即可——这只影响以后的提交。）
5. **英文 README 是否仍然要做，留到开源首发时再定。** 它与"注释用中文"并不直接冲突
   （README 是门面，注释是给贡献者的），但必须承认下面这条代价。

## 代价（写下来，不粉饰）

> **一份中文注释的代码库，把不懂中文的贡献者挡在门外。**

这是一次**单向的、有成本的决定**：将来若想让国际社区参与，注释需要重做一遍。
因此——**若在首发前改变主意，越早改越便宜**。这份 ADR 存在的意义就是把这件事留在纸面上，
而不是留在一个没人记得的口头决定里。

同时它也澄清了另一件事：注释语言的改变**不改变代码的可读性给机器看的那些部分**——
标识符、API 名称、属性键、日志文本保持英文，所以工具链、搜索、以及与上游规范的对照都不受影响。

## 执行方式

分批进行，**按[阅读路线](../reading-the-code.md)的顺序优先**（先翻正在被读的文件）。

每一批都必须验证两件事，缺一不可：

1. **只改了注释**：对 `git diff` 过滤出"非注释行"，结果必须为 **0**。
2. **测试全绿**：纯注释改动不改变行为，所以全量测试必须通过。

第二条是例行公事，第一条才是关键——它把"翻译 1900 行注释"这件本质上危险的批量修改，
变成一个**可以被机器检查**的操作。
